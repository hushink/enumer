# enumer

`enumer` generates type-safe Go enumerations from a YAML manifest. Declare the
type, values and settings once, and get the type declaration, constants and a
set of opt-in methods.

- **YAML as the single source of truth** — no comment DSL, no parsing Go source.
- **String and integer enums** — `string`, `int`, `int8`…`int64`, `uint`…`uint64`.
- **Composable features** — String, Parse, IsValid, text/JSON, SQL, flag, names,
  values, pointers and MustParse. Enable only what you need.
- **Custom targets** — render Markdown, JSON Schema, OpenAPI or any other file
  with `text/template`.
- **Strict, structured diagnostics** — every error carries a file position and a
  stable code; `--json` for CI.
- **Idempotent output** — atomic writes, unchanged files are not rewritten, and
  `enumer check` catches drift.

## Install

The generator requires Go 1.27 or newer. Generated code only requires Go 1.20+.

Add `enumer` as a tool dependency:

```sh
go get -tool github.com/hushink/enumer/cmd/enumer@latest
go tool enumer --help
```

Or install the binary directly:

```sh
go install github.com/hushink/enumer/cmd/enumer@latest
enumer --help
```

## Quick start

```sh
enumer init --package example
enumer generate
```

`enumer.yaml`:

```yaml
version: 1
package: example

defaults:
  features: [string, parse, valid, text]
  naming:
    prefix: type
    identifier: camel

enums:
  - name: Color
    type: string
    doc: Color is an example string enumeration.
    features: [json]
    values:
      - red
      - name: green
        value: GREEN
        aliases: [g]
      - name: blue
        deprecated: use teal

  - name: Status
    type: int32
    features: [json:number, sql, sql:null]
    values:
      - pending
      - running
      - name: failed
        value: 10
```

`enumer generate` writes `color_enum.go` and `status_enum.go` next to the
manifest:

```go
// Code generated by enumer from enumer.yaml; DO NOT EDIT.

package example

// Color is an example string enumeration.
type Color string

const (
	// ColorRed is the "red" value of Color.
	ColorRed Color = "red"
	// ColorGreen is the "GREEN" value of Color.
	ColorGreen Color = "GREEN"
	// ColorBlue is the "blue" value of Color.
	//
	// Deprecated: use teal
	ColorBlue Color = "blue"
)

// String implements fmt.Stringer.
func (x Color) String() string {
	return string(x)
}

// ErrInvalidColor is returned when a value is not valid for Color.
var ErrInvalidColor = errors.New("invalid Color")

// ParseColor converts a string to Color.
func ParseColor(name string) (Color, error) { /* ... */ }

// IsValid reports whether x is a valid Color.
func (x Color) IsValid() bool { /* ... */ }
```

Use the generated API from your code:

```go
c, err := example.ParseColor("g")
if err != nil {
	log.Fatal(err)
}
fmt.Println(c) // GREEN
```

## Manifest

A manifest has a version, an optional package name, defaults, a list of enums
and an optional list of custom targets. See
[docs/manifest-schema.md](docs/manifest-schema.md) for the full reference.

```yaml
version: 1

package: example       # optional when the directory already has Go files

aggregate: false       # true: all enums share one output file
# output: enums_enum.go # aggregate output path; only with aggregate: true

defaults:
  features: [string, parse, valid, text]
  disableFeatures: []
  naming:
    prefix: type       # type | none | literal:<prefix>
    identifier: camel  # camel | raw
    extraInitialisms: [GRPC]
    disableInitialisms: false
  parse:
    caseSensitive: true
  output:
    suffix: _enum.go
    dir: ""
  comments: auto       # auto | none
  allowDuplicateValues: false

enums:
  - name: Color
    type: string
    doc: Color is an example string enumeration.
    package: example   # optional per-enum package override
    output: color_enum.go # optional per-enum output path
    features: [json]
    disableFeatures: []
    start: 0           # numeric enums only
    allowDuplicateValues: false
    values:
      - red
      - name: green
        value: GREEN
        doc: A custom green.
        aliases: [g]
        deprecated: true
      - name: blue
        number: 3      # required by sql:int on string enums
```

Value names are converted to Go identifiers. `http_status` becomes
`ColorHTTPStatus` by default; `blue-green` becomes `ColorBlueGreen`. The
canonical text stays exactly as written unless a string enum supplies `value`.

### Types

| Type | Kind |
| --- | --- |
| `string` | string |
| `int`, `int8`, `int16`, `int32`, `int64` | signed integer |
| `uint`, `uint8`, `uint16`, `uint32`, `uint64` | unsigned integer |

`type` defaults to `string`. Numeric values may be explicit (`value: 10`) or
auto-incremented from `start` (default `0`); an explicit value resets the
sequence for the following auto values. Values are range-checked against the
underlying type.

## Features

Features are additive on top of `defaults.features`. The default set is
`[string, parse, valid, text]`.

| Feature | Generated API |
| --- | --- |
| `string` | `String() string` |
| `parse` | `ErrInvalid<Name>`, `Parse<Name>(string) (<Name>, error)` and the value map |
| `valid` | `IsValid() bool` |
| `mustparse` | `MustParse<Name>(string) <Name>` |
| `text` | `MarshalText` / `UnmarshalText` (also enables default JSON encoding) |
| `json` | Explicit name-based `MarshalJSON` / `UnmarshalJSON` |
| `json:number` | Numeric JSON for integer enums |
| `sql` | `Scan(sql.Scanner)` / `Value(driver.Valuer)` |
| `sql:int` | String enums stored as integers; each value needs `number` |
| `sql:null` | `Null<Name>` wrapper with `Scan`/`Value` |
| `flag` | `Set` / `Type`, compatible with `flag` and `pflag` |
| `names` | `<Name>Names() []string` |
| `values` | `<Name>Values() []<Name>` |
| `ptr` | `Ptr() *<Name>` |

Dependencies are resolved automatically:

- `text`, `json` and `flag` require `parse` and `string`.
- `valid` and `mustparse` require `parse`.
- `sql` and `sql:int` require `parse` and `string`.
- `json:number` requires `parse`.
- `sql:null` requires exactly one of `sql` or `sql:int`.

`json` and `json:number` are mutually exclusive, as are `sql` and `sql:int`.

## CLI

```sh
enumer [generate] [paths...]   # generate; no subcommand behaves like generate
enumer check [paths...]        # verify generated files are up to date
enumer init                    # create a sample enumer.yaml
enumer version                 # print the version
```

Paths may be manifest files, directories containing `enumer.yaml`, or
`./...` for recursion.

Global flags:

- `--strict` — treat warnings as errors.
- `--json` — print diagnostics as a JSON report.
- `-v`, `--verbose` — print written and unchanged files.

`generate` also accepts `--dry-run`. `check` accepts `--diff` to print unified
diffs for stale outputs. `init` accepts `--package` and `--force`.

Exit codes:

- `0` success.
- `1` validation or generation failure, or stale output from `check`.
- `2` command line usage error.

## Custom targets

Any file can be rendered from a template. Targets run after Go files are
generated and participate in `enumer check`.

```yaml
targets:
  - template: ./templates/enums.md.tmpl
    output: ENUMS.md
  - template: ./templates/schema.json.tmpl
    output: "{{.Enum.Name}}.json"
    perEnum: true
```

Template data:

- `.Manifest` — the normalized manifest.
- `.Enums` — all enums in the manifest.
- `.Enum` — the current enum when `perEnum` is true.

Functions: `camel`, `snake`, `kebab`, `lower`, `upper`, `title`, `quote`,
`join`, `json`, `jsonPretty`, `default`.

## go:generate

Add a directive to any Go file in the package:

```go
//go:generate enumer generate
```

When `enumer` is a tool dependency, use:

```go
//go:generate go tool enumer generate
```

Then run:

```sh
go generate ./...
```

## Programmatic API

The `model`, `manifest` and `generator` packages are public. Use them directly
when you want to embed `enumer` in another tool:

```go
m, diags := manifest.Load("enumer.yaml")
if diags.HasErrors() {
	log.Fatal(diags.Format())
}

g := generator.New()
result, diags := g.Generate(context.Background(), []*model.Manifest{m}, generator.GenerateOptions{})
if diags.HasErrors() {
	log.Fatal(diags.Format())
}
fmt.Println(result.Changed)
```

Custom features implement `generator.Feature`. Register them on a private
registry:

```go
registry := generator.DefaultRegistry()
if err := registry.Register(myFeature{}); err != nil {
	log.Fatal(err)
}
g := generator.New(generator.WithRegistry(registry))
```

## Why not a comment DSL?

`abice/go-enum` uses `// ENUM(...)` comments above Go type declarations.
`enumer` deliberately takes a different route:

- The manifest is consumable by non-Go tools and languages.
- The generator does not parse or type-check Go packages.
- Features are composable units with declared dependencies instead of one fixed
  template.
- Validation is strict and diagnostics carry source positions and stable codes.
- Custom targets make additional artifacts a first-class concept.

The trade-off is that the generated file owns the type declaration: do not
declare the same type manually in Go source.

```sh
go test ./generator -run TestGolden -update
```

The project is laid out as:

```
cmd/enumer        command entry point
internal/cli      command line wiring
internal/diag     structured diagnostics
internal/naming   identifier conversion
internal/sink     atomic file writes
manifest          YAML schema, loading, validation and normalization
model             public normalized IR
generator         features, rendering, targets and the public generator API
```
