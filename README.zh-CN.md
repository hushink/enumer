# enumer

[English](README.md) | **简体中文**

[![CI](https://github.com/hushink/enumer/actions/workflows/ci.yml/badge.svg)](https://github.com/hushink/enumer/actions/workflows/ci.yml)
[![Go Reference](https://pkg.go.dev/badge/github.com/hushink/enumer.svg)](https://pkg.go.dev/github.com/hushink/enumer)

`enumer` 从 YAML 清单生成类型安全的 Go 枚举。只需声明一次类型、取值和设置，
即可得到类型声明、常量以及一组按需开启的方法。

- **YAML 单一真相源** —— 不使用注释 DSL，不解析业务 Go 源码（`typeMode: auto`
  仅做语法级类型检测）。
- **字符串与整数枚举** —— `string`、`int`…`int64`、`uint`…`uint64`。
- **可组合能力** —— String、Parse、IsValid、文本/JSON/YAML、SQL、flag、names、
  values、指针与 MustParse，按需启用。
- **自定义目标** —— 用 `text/template` 生成 Markdown、JSON Schema、OpenAPI 等
  任意附加文件。
- **严格诊断** —— 每条错误带文件位置和稳定错误码，支持 `--json`。
- **幂等输出** —— 原子写入、内容未变不重写、被移除的枚举会清理，`enumer check`
  检测漂移。
- **标准格式化** —— 生成代码统一使用官方标准库 `go/format`。

## 安装

生成器需要 Go 1.27 或更高版本；生成的代码只要求 Go 1.20+。

作为工具依赖安装：

```sh
go get -tool github.com/hushink/enumer/cmd/enumer@latest
go tool enumer --help
```

或直接安装二进制：

```sh
go install github.com/hushink/enumer/cmd/enumer@latest
enumer --help
```

## 快速开始

```sh
enumer init --package example
enumer generate
```

`enumer.yaml`：

```yaml
version: 1
package: example

defaults:
  features: [string, parse, valid, text, names, values]
  naming:
    prefix: type
    identifier: camel

enums:
  - name: Color
    type: string
    doc: Color is an example string enumeration.
    features: [json]
    values:
      - red
      - name: green
        value: GREEN
        aliases: [g]
      - name: blue
        deprecated: use teal

  - name: Status
    type: int32
    features: [json:number, sql, sql:null]
    values:
      - pending
      - running
      - name: failed
        value: 10
```

`enumer generate` 会在清单旁生成 `color_enum.go` 与 `status_enum.go`：

```go
// Code generated by enumer from enumer.yaml; DO NOT EDIT.

package example

// Color is an example string enumeration.
type Color string

const (
	// ColorRed is the "red" value of Color.
	ColorRed Color = "red"
	// ColorGreen is the "GREEN" value of Color.
	ColorGreen Color = "GREEN"
	// ColorBlue is the "blue" value of Color.
	//
	// Deprecated: use teal
	ColorBlue Color = "blue"
)

// String implements fmt.Stringer.
func (x Color) String() string { return string(x) }

// ParseColor converts a string to Color.
func ParseColor(name string) (Color, error) { /* ... */ }

// IsValid reports whether x is a valid Color.
func (x Color) IsValid() bool { /* ... */ }

// ColorNames returns the names of all Color values in declaration order.
func ColorNames() []string { /* ... */ }

// ColorValues returns all Color values in declaration order.
func ColorValues() []Color { /* ... */ }
```

使用：

```go
c, err := example.ParseColor("g")
if err != nil {
	log.Fatal(err)
}
fmt.Println(c) // GREEN
```

## 清单配置

清单包含版本、可选包名、默认配置、枚举列表和可选的自定义目标。完整字段说明见
[配置指南](docs/configuration.zh-CN.md) 与
[清单 schema](docs/manifest-schema.zh-CN.md)。

```yaml
version: 1
# extends: ../base.yaml # 可选：继承共享默认配置

package: example       # 目录内已有 Go 文件时可省略

aggregate: false       # true：本清单所有枚举合并为一个文件
# output: enums_enum.go # 聚合输出路径；仅 aggregate: true 时有效

defaults:
  features: [string, parse, valid, text, names, values]
  disableFeatures: []
  naming:
    prefix: type       # type | none | literal:<前缀>
    identifier: camel  # camel | raw
    extraInitialisms: [GRPC]
    disableInitialisms: false
  parse:
    caseSensitive: true
  output:
    suffix: _enum.go
    dir: ""
  comments: auto       # auto | none
  allowDuplicateValues: false
  typeMode: auto       # auto | emit | existing

enums:
  - name: Color
    type: string
    doc: Color is an example string enumeration.
    # comment: 可选的注释覆盖，优先级高于 doc。
    comments: auto     # 枚举级 auto | none 覆盖
    package: example   # 可选的枚举级包名覆盖
    output: color_enum.go # 可选的枚举级输出路径
    features: [json]
    disableFeatures: []
    start: 0           # 仅数字枚举有效
    allowDuplicateValues: false
    values:
      - red
      - name: green
        value: GREEN
        comment: 自定义绿色注释。
        aliases: [g]
        deprecated: true
      - name: blue
        number: 3      # 字符串枚举启用 sql:int 时必填
```

取值名会转换为 Go 标识符：`http_status` → `ColorHTTPStatus`，
`blue-green` → `ColorBlueGreen`。字符串枚举未提供 `value` 时，规范文本等于取值名。

`doc` 与 `comment` 都可以覆盖自动生成注释；两者同时存在时 `comment` 优先。
`comments: none` 可关闭某个枚举的自动注释，但用户注释和弃用说明仍会保留。

### 共享默认配置

使用 `extends` 从基础 YAML 继承 `defaults`：

```yaml
# base.yaml
version: 1
defaults:
  features: [string, parse, valid, text, names, values]
  naming:
    prefix: type
```

```yaml
# color/enumer.yaml
version: 1
package: color
extends: ../base.yaml
enums:
  - name: Color
    values: [red, green, blue]
```

只继承 `defaults`；基础文件中的 `enums`、`targets`、`package`、`aggregate` 和
`output` 会被忽略。嵌套的 `naming`、`parse`、`output` 按字段合并，列表类配置
（如 `features`）整体替换，`features: []` 表示清空。循环继承会报错。

### 类型声明

`typeMode` 控制生成文件是否声明枚举类型：

- `auto`（默认）：扫描目标包。没有声明时生成类型；已有声明时只生成常量和方法；
  遇到类型别名、泛型或底层类型不一致时报错。
- `emit`：总是生成类型。其它文件中已有同名声明时报错。
- `existing`：从不生成类型。声明必须存在且底层类型一致。

```yaml
enums:
  - name: Color
    type: string
    values: [red, green, blue]
```

```go
// types.go
package example

// Color is a hand-written type.
type Color string
```

默认 `auto` 模式下，enumer 检测到该声明后只生成常量与方法；如果文件不存在，则
按清单生成类型。检测使用 `go/parser` 做语法级扫描，不会加载或类型检查整个包。

### 枚举值列表导出

`names` 与 `values` 已包含在默认能力集中，直接导出取值列表：

```go
ColorNames()   // []string{"red", "GREEN", "blue"}
ColorValues()  // []Color{ColorRed, ColorGreen, ColorBlue}
```

可通过 `disableFeatures: [names]` 关闭，或在覆盖 `features` 的清单中显式启用。

### 注释覆盖

每个枚举和取值都支持 `doc` 或 `comment` 覆盖生成注释，`comment` 优先；
`comments: auto|none` 可按枚举设置。

```yaml
enums:
  - name: Color
    comment: Color is the public color enumeration.
    comments: none
    values:
      - name: red
        comment: Red is the default color.
```

### 类型

| 类型 | 类别 |
| --- | --- |
| `string` | 字符串 |
| `int`、`int8`、`int16`、`int32`、`int64` | 有符号整数 |
| `uint`、`uint8`、`uint16`、`uint32`、`uint64` | 无符号整数 |

`type` 默认为 `string`。数字枚举可显式指定 `value`，也可从 `start`（默认 `0`）
自动递增；显式值会重置后续递增值。所有取值都会做底层类型范围检查。

## 能力

能力在 `defaults.features` 基础上按枚举叠加。默认集合为
`[string, parse, valid, text, names, values]`；显式空列表 `features: []`
会关闭全部能力。

| 能力 | 生成 API |
| --- | --- |
| `string` | `String() string` |
| `parse` | `ErrInvalid<Name>`、`Parse<Name>(string) (<Name>, error)` 与取值映射 |
| `valid` | `IsValid() bool` |
| `flags` | `Has`、`With`、`Clear`、`Toggle`、`Flags`，以及组合感知的 `String`/`Parse`/`IsValid` |
| `mustparse` | `MustParse<Name>(string) <Name>` |
| `text` | `MarshalText` / `UnmarshalText`（同时启用默认 JSON 编码） |
| `json` | 显式基于名称的 `MarshalJSON` / `UnmarshalJSON` |
| `json:number` | 整数枚举的数字 JSON |
| `yaml` | `MarshalYAML` / `UnmarshalYAML` |
| `sql` | `Scan(sql.Scanner)` / `Value(driver.Valuer)` |
| `sql:int` | 字符串枚举以整数入库；每个取值需要 `number` |
| `sql:null` | `Null<Name>` 可空包装，含 `Scan`/`Value`/JSON |
| `flag` | `Set` / `Type`，兼容标准库 `flag` 与 `pflag` |
| `names` | `<Name>Names() []string` |
| `values` | `<Name>Values() []<Name>` |
| `ptr` | `Ptr() *<Name>` |

依赖会自动补齐：

- `text`、`json`、`flag` 依赖 `parse` 与 `string`。
- `valid`、`mustparse` 依赖 `parse`。
- `flags` 依赖 `string`、`parse`、`valid`，且只支持无符号整数。
- `sql`、`sql:int` 依赖 `parse` 与 `string`。
- `json:number` 依赖 `parse`。
- `sql:null` 需要 `sql` 与 `sql:int` 中恰好一个。

`json` 与 `json:number` 互斥，`sql` 与 `sql:int` 互斥。

### 位标志

在无符号整数枚举上启用 `flags`，每个取值为 0 或 2 的幂：

```yaml
enums:
  - name: Permission
    type: uint32
    features: [flags]
    values:
      - name: none
        value: 0
      - name: read
        value: 1
      - name: write
        value: 2
```

```go
PermissionRead | PermissionWrite // String -> "read|write"
ParsePermission("read|write")   // PermissionRead | PermissionWrite
x.Has(PermissionRead)           // 是否包含全部位
x.With(PermissionExecute)       // 设置
x.Clear(PermissionWrite)        // 清除
x.Toggle(PermissionWrite)       // 翻转
x.Flags()                       // []Permission{PermissionRead, PermissionWrite}
```

`String`、`Parse`、`IsValid` 均为组合感知；`json`、`text`、`yaml`、`sql`、`flag`
会自动复用这些语义。`flags` 拒绝重复值、多个零值和非 2 的幂取值。

## CLI

```sh
enumer [generate] [paths...]   # 生成；无子命令等价于 generate
enumer check [paths...]        # 校验生成物是否最新
enumer init                    # 创建示例 enumer.yaml
enumer version                 # 打印版本
```

路径可以是清单文件、包含 `enumer.yaml` 的目录，或 `./...` 递归模式。

全局参数：

- `--strict`：把警告升级为错误。
- `--json`：输出结构化 JSON 诊断。
- `-v`、`--verbose`：打印写入与未变化的文件。
- `--no-prune`：保留已不再声明的枚举所对应的生成文件。

`generate` 额外支持 `--dry-run`；`check` 支持 `--diff` 输出统一 diff。
`init` 支持 `--package` 与 `--force`。

退出码：

- `0` 成功。
- `1` 校验/生成失败，或 `check` 发现过期文件。
- `2` 命令行用法错误。

## 清理

`enumer generate` 会删除那些带有当前清单精确生成头、但已不再产出的 `.go` 文件。
从 `enumer.yaml` 移除枚举后，下一次生成会删除对应的旧 `_enum.go`。

匹配是严格的：手写文件、其它清单生成的文件和自定义目标输出不会被删除。
`enumer check` 会把孤儿生成文件报告为过期。使用 `--no-prune` 可以保留它们。

## 自定义目标

任意文件都可以由模板生成；目标在 Go 文件生成后执行，并参与 `enumer check`。

```yaml
targets:
  - template: ./templates/enums.md.tmpl
    output: ENUMS.md
  - template: ./templates/schema.json.tmpl
    output: "{{.Enum.Name}}.json"
    perEnum: true
```

模板数据：

- `.Manifest` —— 规范化后的清单。
- `.Enums` —— 清单内全部枚举。
- `.Enum` —— `perEnum: true` 时的当前枚举。

模板函数：`camel`、`snake`、`kebab`、`lower`、`upper`、`title`、`quote`、
`join`、`json`、`jsonPretty`、`default`。

输出路径以 `.go` 结尾的目标会使用 `go/format.Source` 格式化，因此必须渲染一个
完整的 Go 文件。

## go:generate

在包内任意 Go 文件中加入：

```go
//go:generate enumer generate
```

使用工具依赖时：

```go
//go:generate go tool enumer generate
```

然后运行：

```sh
go generate ./...
```

## 格式化

生成的 Go 文件统一使用官方标准库 `go/format`（`format.Source`）格式化；
输出路径以 `.go` 结尾的自定义目标也会格式化，无法解析时生成失败并报
`format-error`。
